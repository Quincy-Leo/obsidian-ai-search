# obsidian-ai-search

[English](./README.md) | **简体中文**

通过**AI决策模型**快速进行**全文或全仓库模糊搜索**，无需精确词语匹配，无需复杂的搜索引擎。

默认预设对接 [Jev](https://docs.typesafe.ai)（TypeSafe 的决策模型），它的 `systemone` 接口返回的是概率而不是文本。任何同协议的接口都可以通过"自定义"预设接入。

本插件完全使用 Claude Opus 5 编写。

- **最低 Obsidian 版本**：1.4.0
- **平台**：仅桌面端
- **界面语言**：简体中文 / English
- **License**：MIT

---

## ✨ 特性

- 🔎 **两种范围**：搜当前文档，或按目录和拓展名筛选后搜全库。
- 📊 **按相关度排序**：每条结果都带模型给出的概率，显示成百分比，也是排序依据。
- 🚦 **可控的调用量**：并发数、每请求 token 数、单题 token 数、每秒请求数、每秒 token 数都可配置。
- ⏹️ **随时可停**：搜索中有进度条和"终止"按钮，终止后把已拿到的结果排序展示。
- 🌏 **双语界面**：所有标签、提示和报错都有中英文两版。
- 🙈 **不留痕迹**：不建索引、不存历史记录，除设置文件外不写盘。

## 🚀 安装

```bash
git clone <本仓库>
cd obsidian-ai-search
npm install
# 把 TARGET_DIR 指向 <你的仓库>/.obsidian/plugins/ai-search，然后：
./build.sh
```

`build.sh` 会执行 `npm run build`（esbuild 把 `src/*.js` 打包成 `main.js`），再把 `main.js` 和 `manifest.json` 复制到目标目录。在*设置 → 第三方插件*里启用 **ai-search**，然后填入模型密钥。

## 🖱️ 触发方式

| 入口        | 方式                      |
| --------- | ----------------------- |
| 命令面板      | `ai-search` → "AI 模糊搜索" |
| ribbon 图标 | 左侧边栏的 `text-search` 图标  |

两者打开的是同一个搜索弹窗：

- 最左侧是输入框，最右侧依次是**搜本文**和**搜全库**。在输入框里敲回车等同于**搜本文**，Shift+回车等同于**搜全库**；带其他修饰键（Ctrl / Cmd / Alt）的回车不响应。鼠标悬浮到按钮上会显示对应快捷键。
- 弹窗没有关闭按钮 —— 点击弹窗以外的任意区域即消失。重新触发插件功能再打开时，显示的内容和消失之前完全一样；搜索在弹窗关闭期间也会继续跑。
- 修改输入内容（无论增加或删除）会清掉上次的结果并终止在跑的搜索，因为那些结果回答的是旧问题。
- 搜索进行中，结果列表的位置是进度条，进度条左侧有"终止"按钮。终止后按已获得的结果排序展示。
- 每条结果第一行用加粗小字显示文件名和相关度百分比，随后最多两行显示命中的段落。点击即打开该文件并跳到对应行，弹窗同时消失。

## ⚙️ 设置项详解

### 语言

界面语言，默认中文。命令名、ribbon 提示语和所有消息都跟着切换。

### AI 相关

| 设置项 | Jev 预设默认值 | 自定义预设默认值 |
| --- | --- | --- |
| 预设 | `Jev` | — |
| Base URL | `https://api.typesafe.ai` | 留空 |
| 模型名称 | `jev-latest` | 留空 |
| 模型密钥 | 留空 | 留空 |
| 最大并发请求数 | 8 | 留空 → 串行 |
| 每请求最大 token 数 | 64000 | 留空 → 只受每秒预算份额约束 |
| 单题最大 token 数 | 32000 | 留空 → 不拆分 |
| 每秒请求上限 | 80 | 留空 → 不限制 |
| 每秒 token 上限 | 100000 | 留空 → 不限制 |
| 相关度阈值 | 0.5 | 0.5 |

每个预设在 `data.json` 的 `presets` 下用一个子对象独立保存、更新、读取，所以切换预设不会覆盖另一个预设的值。Jev 的默认值按公开限制（80 请求/s、100K tokens/s、每请求 64k tokens、`state` 加最长单题 32k tokens）硬编码在 `src/settings.js` 里，插件运行时不去读任何文档。**重置 AI 设置**只重置当前选中的那个预设。

请求路径 `/v1/systemone` 由代码拼在 base URL 后面。

### 目录相关

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 搜索哪些目录 | 留空 → 整个仓库 | 相对仓库根目录的路径，一行一个，递归包含子目录 |
| 排除哪些目录 | 留空 → 不排除 | 一行一个，递归；与包含列表冲突时按排除处理 |
| 搜索哪些拓展名 | `md,txt` | 英文逗号分隔，不带点号 |

仅支持纯文本文档。非纯文本会被忽略 —— 先按拓展名过滤，再加一道保险：内容里含 NUL 字节的文件直接跳过。**重置目录设置**恢复上面三项；**重置所有设置**还会一并恢复语言和两个预设。

## 🏗️ 一次搜索的流程

1. **切分**：把文件切成判断单元 —— 每行一个，但长度不足 10 个字符的行并进下一行。代码块和表格例外：整块拼成一个单元，不按行拆（单独一行表格行或一行代码脱离整块后没有判断价值，拼起来还能把一块表格的 N 道题压成 1 道）。空行、ATX 标题、代码块围栏那两行、表格的分隔行和开头的 YAML frontmatter 会跳过；围栏里的代码本身仍然参与搜索。只有排版符号（`---`、`| --- |`）的单元会被丢掉。每个单元记住自己的第一行行号（代码块记开围栏那一行），点击结果就跳到这里。
2. **组批**：搜索词和判定规则放进 `state`，每个单元各占一道 `noul` 题、正文放在该题的 `instructions` 里。这样一个请求能判断多段正文，且各段之间互不干扰；整批共用的那句规则只在 `state` 里付一次钱，不随题数翻倍。"搜索词 + 单段正文"超过"单题最大 token 数"的单元会被切成多道题（切点尽量落在换行或空格上），后半截不会被丢掉；同一个单元只出一条结果，分数取各段里最高的那个，界面上展示的仍是完整文本。
3. **调度**：按"最大并发请求数"起对应数量的 worker，前面挡一个滑动窗口限流器，同时约束两个速率上限。token 预算在发送前按请求体长度估算（刻意高估）。单个请求的大小取"每请求最大 token 数"和"每秒 token 上限 ÷ 并发数"里较小的那个：把请求填到接口上限最省 token，却最费时间 —— Jev 问 60 道题和问 1 道题耗时差不多，而越肥的请求占掉越多每秒预算，限流器就让其余 worker 干等，配置的并发数形同虚设。按份额切批后每个 worker 都能同时拿到配额。
4. **重试**：HTTP 429 / 529 / 5xx 和网络异常会重试 —— 共 3 次，500ms 指数退避。HTTP 400 / 401 / 403 / 422 则直接结束整次搜索，因为重试改变不了结果。重试额度用完的批次记为失败，结束时统一提示，其余批次照常跑完。
5. **排序**：把概率达到阈值的单元从高到低排好后渲染。

## 🧱 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/main.js` | 插件注册：命令、ribbon 图标、设置页、生命周期 |
| `src/settings.js` | 本地化文案、配置版本、预设、设置页 UI |
| `src/search.js` | 文本切分、文件筛选、调度、限流、状态 |
| `src/window.js` | 搜索弹窗（纯展示层） |
| `src/ai.js` | 请求组装、HTTP、错误分类、重试 |

搜索状态存在 `search.js` 的 `SearchController` 上而不是弹窗上 —— 这是"关掉再打开内容不变"的实现方式，也让搜索能在弹窗关闭期间继续跑。

## 🔐 配置文件

`data.json` 有一个 `version` 字段，当前固定为 `1`。

- **读配置时**：缺失、非整数或小于 1 都报非法字段；大于 1 报配置版本高于插件版本。两种情况下插件**直接拒绝加载** —— 不注册命令、ribbon 图标和设置页，避免在一份读不懂的配置上继续跑并把它覆盖掉。
- **写配置时**：发现磁盘上的文件版本更低，先备份成 `data.json.bak` 再写新文件；版本更高则拒绝写入。

模型密钥以明文存在 `data.json` 里（和其他 Obsidian 插件的凭据一样），只会以 `Authorization: Bearer` 请求头发往你自己配置的 base URL。

## ⚠️ 已知限制

- **仅支持文本搜索**：出于简洁考虑，目前只支持文本搜索。如果您有图片或其他非纯文本文档的搜索需求，欢迎提issue或pr
- **开销和耗时随仓库规模线性增长**：每一行都要过一次模型。按默认限制，一个请求能装几百行普通长度的正文，10 万行的仓库约几百个请求，建议先用目录筛选缩小范围。
- **不做缓存**：重复同样的搜索会重新调用全部接口，这是刻意的设计。
- **单行上下文**：一行（合并过短行之后）是独立判断的，所以代词很多的句子得分可能低于它所在的整段。
- **自定义接口必须是 `systemone` 结构**：请求 `{state, questions}`，响应 `{answers: {id: {noul}}}`。
